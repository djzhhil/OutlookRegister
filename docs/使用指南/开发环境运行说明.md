## 你需要准备什么？

### 1. 软件环境（必做）

| 准备项 | 说明 | 本机实测 |
|--------|------|----------|
| Python 3.10+ | 用来跑脚本 | 已有 3.12 |
| 项目依赖 | `faker` / `requests` / `playwright` / `patchright` | 已装入 `.venv` |
| Chromium（由 patchright 下载） | **不用自己装 Chrome**；执行 `patchright install chromium` | 已下载到缓存 |
| 系统图形库 | Linux 上若缺库，可执行 `patchright install-deps chromium` | 已处理 |
| 显示器 / 虚拟显示 | 项目**强制有界面启动**（`headless=False`），需要 `DISPLAY` | 本机 `DISPLAY=:0`，有界面启动成功 |

> 结论：浏览器不用单独去官网装；用 patchright 自带的 Chromium 即可。  
> 只有当你改用 `playwright` 模式时，作者才建议自备「能过浏览器指纹检测」的指纹浏览器，并填写 `browser_path`。

### 2. 网络代理（强烈建议，作者几乎当成必选项）

| 准备项 | 说明 |
|--------|------|
| HTTP/SOCKS 代理 | 填到 `config.json` 的 `proxy` |
| 质量要求 | 住宅/干净 IP 成功率更高；同一 IP 短时间不要狂注册 |
| 格式示例 | `http://127.0.0.1:7897` 或 `http://用户:密码@主机:端口` |

作者原话大意：**只改代理就能用 patchright（不开启 OAuth2 时）**；IP 与成功率高度相关。

**本机现状（2026-08-01）：**

- 配置里写的是 `http://127.0.0.1:7897`
- 当前该端口**没有可用代理**（连接被拒绝）
- 因此用配置里的代理访问微软会失败：`ERR_PROXY_CONNECTION_FAILED`
- **不走代理直连**可以打开 `login.live.com`（连通性 OK），但真实注册仍强烈依赖代理质量

### 3. 可选：OAuth2（默认不必开）

只有当你还要拿到微软 Graph 访问令牌时才需要：

1. 去 Azure 创建应用，拿到 `client_id`、`redirect_url`
2. 在 `config.json` → `oauth2` 里设 `enable_oauth2: true` 并填写字段  
开发环境第一次试跑建议保持 `false`。

### 4. 合规提醒

批量自动注册通常违反微软服务条款。开发测试请控制次数、仅用于合法授权场景。

## 推荐安装步骤（干净环境）

在项目根目录执行：

```bash
cd /root/projects/OutlookRegister

# 1. 虚拟环境
python3 -m venv .venv
source .venv/bin/activate

# 2. Python 包
pip install -r requirements.txt

# 3. 下载 Chromium（不用自己找浏览器安装包）
patchright install chromium

# 4. Linux 若缺系统依赖（可选，缺库再跑）
# sudo patchright install-deps chromium
```

WSL2 注意：需要能弹出图形窗口（WSLg 或外部 X Server）。本机已测有界面启动成功。

## 跑之前先改配置

编辑 `config.json`，开发环境建议先「小而安全」：

```json
{
  "choose_browser": "patchright",
  "email_suffix": "@outlook.com",
  "proxy": "http://你的代理地址:端口",
  "bot_protection_wait": 16,
  "max_captcha_retries": 3,
  "concurrent_flows": 1,
  "max_tasks": 1,
  "oauth2": {
    "enable_oauth2": false
  }
}
```

建议：

- `concurrent_flows`: 先设 `1`（一次只开一个浏览器，方便观察）
- `max_tasks`: 先设 `1`（只试注册一个）
- `proxy`: 改成你本机真实可用的代理
- `choose_browser`: 保持 `patchright`

## 开发环境下建议的验证顺序

不要一上来就跑大批量。建议分三档：

### A. 环境冒烟（不注册账号）

验证：依赖已装、Chromium 能启动、网络能到微软。  
（本机已做过：浏览器启动 OK；直连登录页 OK；配置代理当前不可用。）

### B. 单任务试跑（真正走注册页）

1. 先把代理启动好，确认 `proxy` 可用  
2. `max_tasks=1`、`concurrent_flows=1`  
3. 运行 `python main.py`  
4. 看窗口是否进入注册页、验证码是否为「按压」类、是否写入 `Results`

### C. 小批量

确认单次稳定后，再把 `max_tasks` / `concurrent_flows` 略微加大。同 IP 不要短时间大量并发。

## 常见失败对照

| 现象 | 更可能的原因 |
|------|----------------|
| `ERR_PROXY_CONNECTION_FAILED` | 代理没开、端口错、协议不对 |
| `IP质量不佳，无法进入注册界面` | 代理 IP 差或被风控 |
| `注册频率过快 / 异常活动` | 同 IP 注册太勤，或环境像机器人 |
| `FunCaptcha / 验证码类型错误` | 不是按压验证码，本项目覆盖不了 |
| 浏览器弹不出来 | `DISPLAY` 未设置；WSL 无图形支持 |
| 点不到按钮 / 超时 | 微软改了页面，选择器失效 |
