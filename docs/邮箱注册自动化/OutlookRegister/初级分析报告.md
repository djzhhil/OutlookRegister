# OutlookRegister 初级分析报告

> 面向：不懂编程的读者  
> 仓库：`LainsNL/OutlookRegister`  
> 分析日期：2026-08-01  
> 分析范围：本地克隆的 `main` 分支（最新提交约 2026-07-26）

---

## 一句话说明

这是一个**自动注册 Outlook / Hotmail 邮箱**的小工具：它像「请了一个会操作电脑的助手」，自动打开微软注册网页、填写信息、处理验证码，并把成功注册的账号记到文件里。

---

## 它解决什么问题？

人工注册微软邮箱通常要：打开网页 → 起用户名 → 设密码 → 填生日姓名 → 过验证码 → 记住账号。

本项目把上述步骤做成**可批量、可重复运行**的流程，适合需要大量测试账号、或研究注册流程的人。作者也提醒：页面经常变，**不保证一直能用**。

---

## 用生活例子理解「它怎么工作」

可以把整个程序想成一条流水线：

```text
你设定规则（配置文件）
        ↓
程序同时派出几个「虚拟助手」（多开浏览器）
        ↓
每个助手：打开注册页 → 填写 → 过验证码 → 记下结果
        ↓
全部结束后，告诉你成功了几个、失败了几个
```

更细一点：

1. **准备身份**  
   程序随机生成邮箱名、强密码，以及假的姓名、生日（看起来像真人资料）。

2. **打开微软注册页**  
   通过浏览器访问 Outlook 的「创建账户」页面（不是自己写一个微软服务器，而是去官网注册）。

3. **像人一样操作**  
   鼠标慢慢移动、一个字一个字输入，中间还会停顿，降低被当成机器人的概率。

4. **处理验证码**  
   主要应对「按压 / 再次按下」这类验证；若遇到另一种更复杂的验证码，会直接判失败。

5. **保存结果**  
   成功账号写进 `Results` 文件夹里的文本文件，方便以后查看。

6. **（可选）拿登录凭证**  
   若打开 OAuth2 开关，还会继续申请「访问令牌」，相当于拿到后续用程序读邮件等能力的钥匙（需你自己在微软云平台申请应用信息）。

---

## 项目里有哪些「零件」？

不用看代码，按职责理解即可：

| 零件（文件/文件夹） | 通俗作用 |
|---------------------|----------|
| `main.py` | 总开关：读配置、决定开几个助手、统计成功失败 |
| `config.json` | 遥控器：代理、邮箱后缀、同时注册几个、要不要拿令牌等 |
| `utils.py` | 生成随机邮箱名和密码 |
| `controllers/` | 「浏览器操作手册」：怎么点、怎么填、怎么过验证码 |
| `get_token.py` | （可选）注册成功后再去微软拿访问令牌 |
| `Results/` | 成绩单：成功账号、令牌等输出文件 |
| `requirements.txt` | 需要安装的外部工具清单 |
| `readme.md` | 作者自己的简短使用说明 |

代码量大约 **750 行**，属于中小型脚本项目，结构相对直接。

---

## 你可以调的主要旋钮（配置）

都在 `config.json` 里，含义如下：

| 配置项 | 白话解释 | 当前仓库默认倾向 |
|--------|----------|------------------|
| 浏览器类型 | 用 `patchright`（推荐）或 `playwright` | `patchright` |
| 邮箱后缀 | `@outlook.com` 或 `@hotmail.com` | `@outlook.com` |
| 代理 | 网络中转地址；作者强调**代理质量几乎决定成败** | 本机 `7897` 端口示例 |
| 等待时间 | 注册过程中故意多等一会儿，减轻风控 | 约 16 秒量级 |
| 验证码重试 | 按压验证码最多试几次 | 3 次 |
| 并发数 | 同时开几个浏览器一起注册 | 3 |
| 总任务数 | 一共打算注册多少个 | 5 |
| OAuth2 | 要不要额外拿令牌；默认关闭 | 关闭 |

作者原话要点：**同一 IP 短时间不要狂注册**；IP 越好，成功率越高。

## 一次注册大致会经历什么？

成功路径可以记成 6 步：

1. 进入创建账户页（进不去 → 多半是 IP 不行）  
2. 选域名（Outlook 或 Hotmail）并输入邮箱名  
3. 设密码  
4. 填生日、姓名  
5. 过按压验证码  
6. 写入结果文件；若开启 OAuth2，再进邮箱并申请令牌  

常见失败原因（程序里也会打印类似提示）：

- IP 质量差，进不了注册页  
- 注册太勤，被提示「异常活动」或维护  
- 验证码类型不是程序认识的那种（例如 FunCaptcha）  
- 页面结构被微软改了，按钮找不到（作者说「选择器经常更新」）

---

## 成功后，结果存在哪里？

| 文件 | 什么时候出现 | 里面大致是什么 |
|------|--------------|----------------|
| `Results/unlogged_email.txt` | 只注册、不开 OAuth2 | `邮箱: 密码` |
| `Results/logged_email.txt` | 开启了 OAuth2 且注册成功 | `邮箱: 密码` |
| `Results/outlook_token.txt` | OAuth2 令牌也拿到了 | 邮箱、密码、刷新令牌、访问令牌等 |

这些都是普通文本，用记事本就能打开。

## 优缺点（给决策用）

**优点**

- 目标清晰：专注 Outlook / Hotmail 网页注册  
- 有「拟人」操作（滑动鼠标、慢速输入），不是简单粗暴狂点  
- 支持少量并发，适合小批量尝试  
- 可选拿到微软 Graph 相关令牌，方便后续自动化读信/发信（需合规使用）  
- 仓库近期仍有更新（例如 2026-07 仍有提交）

**缺点 / 风险**

- **强依赖网络环境**：没有靠谱代理，成功率通常很低  
- **脆弱**：微软一改页面或风控策略，工具就可能失效  
- **没有图形界面**：需要改配置文件、在命令行运行（对小白有门槛）  
- **合规边界**：批量自动注册通常违反微软服务条款；仅应在合法、授权场景使用  
- 验证码能力有限：主要覆盖按压类，复杂验证会失败

## 和同类项目比，它处在什么位置？

在 GitHub 同类「Outlook 注册机」里，本仓库（`LainsNL/OutlookRegister`）属于**关注度高、近期仍更新**的主线之一。  
社区还有功能更花的衍生版（例如加强 OAuth、加图形界面），但理解「注册机是什么」时，**从本仓库入手最合适**。

## 不懂代码的人，若只想「搞懂它」，记住这 5 点即可

1. 它是**自动填微软官网注册表**的助手，不是微软官方产品。  
2. 成败几乎取决于：**代理 IP + 浏览器环境 + 验证码是否匹配**。  
3. 你主要改一个文件：`config.json`。  
4. 结果看 `Results` 文件夹。  
5. 页面和风控会变，今天能用不代表明天还能用。

## 附录：运行前通常需要准备什么？（概念级）

不必会写代码，但要具备这些条件：

1. 一台能装 Python 的电脑  
2. 按说明安装依赖，并装好浏览器组件（作者推荐 patchright + Chromium）  
3. 可用的代理（作者要求本地搭代理池）  
4. 改好 `config.json` 后执行启动命令（作者文档为 `python main.py`）  
5. 若需要令牌：去微软 Azure 创建应用，填入 `client_id`、`redirect_url` 等  

更细的操作步骤，可后续放在本仓库文档分类「使用指南」中单独撰写。
